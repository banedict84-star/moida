# AI 직원 카탈로그

`모이다_AI직원_300개_목록.xlsx`의 `AI직원 300!A6:L305`에서 300개 직무를 가져왔습니다. M001–M300 ID, 이름, 분야, 직무, 업무, 결과물, 근무 방식, 실행 조건, 필요 자료·연결, 승인·검토 조건, 출시 제안, 원본 구현 상태를 보존합니다. 원본 파일은 수정하지 않습니다.

## 현재 제공 범위

- 기존 직원 8명과 고용 ID를 유지하고 300명을 추가합니다.
- 24명 단위 페이지, 이름·직무·분야·ID 검색, 분야 필터, 1차 출시 후보 필터를 제공합니다.
- 신규 직원 사진은 `assets/staff/M001.webp`부터 `M300.webp`까지 개별 AI 가상 인물로 제공됩니다. 384–512px WebP 사진은 지연 로딩하며 실존 인물의 사진이 아닙니다.
- 고용한 직원에게 직접 지시하거나 이름·직무·ID로 자동 배정합니다. 한 요청 최대 8명, 동시 실행 3명 제한을 유지합니다.
- 서버에서 각 직원 ID를 개별 작업으로 실행하고 해당 직무의 결과물·검토 조건에 따라 문안을 작성·분석합니다. 기존 비서실장 검수와 보고 경로를 사용합니다.
- 자료실은 현재 계정에 속한 자료만 조회합니다. 일부 일정 직무에는 기존 캘린더 읽기 도구, 의정 분야에는 법령 읽기 도구를 연결합니다.

## 아직 연결되지 않은 기능

원본의 '조건부 자동화'와 트리거는 계획 메타데이터입니다. 이번 변경은 정기 실행이나 이벤트 감시를 등록하지 않습니다. 메일·SNS 발송, 외부 예약, 결제, 재고·회원·거래 DB 변경, 고유 이미지·영상·음성·PDF 제작을 이 직원 실행 경로에 새로 연결하지 않습니다. 이런 요청은 자료 기반 문안·제작 사양과 다음 단계를 제공하며, 실제 파일 생성이나 외부 실행을 완료했다고 보고하지 않도록 지침과 화면에 명시합니다. 따라서 300개 업무의 전체 자동화 완료를 의미하지 않습니다.

## 배포

`office-staff-catalog.js`는 브라우저와 Worker가 함께 사용하는 정의입니다. Worker 배포 후 `/health`의 `officeStaffCatalogVersion: 1` 및 `officeStaffCount: 300`을 확인합니다. 화면이 먼저 갱신되면 새 직원 요청은 서버 버전 확인 후에만 접수합니다. 기존 8명 요청은 그대로 동작합니다. 카탈로그 로드 실패 시 고용 설정을 덮어쓰지 않고 오류를 표시합니다.

## 검증

`node --test tests/office-staff-catalog.test.mjs`는 300명 전원의 실행 계약, 동일 분야 직원의 개별 작업, 최대 배정 수, 역할별 읽기 권한, ID 매칭, 비서실장 검수 경로를 확인합니다. 모델 응답은 모의 응답으로 검증하며 유료 실모델·운영 계정 호출을 증명하지 않습니다.

브라우저에서 308개 ID 접근, 페이지 간 선택, 기존 고용 보존, 직접/자동 배정, 분야·출시 필터, 모바일 가로 넘침, 저장 실패 복구, 계정 전환 초기화를 확인했습니다. 원본 300개 행과 생성된 카탈로그의 12개 필드를 대조했습니다.
