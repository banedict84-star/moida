# 모이다 일정봇 — 구글 캘린더 연동 오류(403 disallowed_useragent) 수정 안내

## 증상
카톡 일정봇에서 **"내 캘린더 다시 연동하기"** 버튼을 누르면 구글 로그인 화면에서 아래 오류가 뜬다.

> 액세스 차단됨: MOIDA의 요청이 Google 정책을 준수하지 않습니다
> **403 오류: `disallowed_useragent`**

## 원인
구글은 **2021-09-30부터 인앱 웹뷰(임베디드 브라우저)에서의 OAuth 로그인을 차단**한다.
카톡 버튼을 누르면 **카카오톡 인앱 브라우저**로 열리기 때문에 차단된다. (앱 설정·구글 콘솔 문제 아님)

## 해결 방향 (선택: 개인이 폰에서 승인 / 외부 브라우저 방식)
구글 로그인 링크를 **기본 브라우저(크롬·사파리)** 로 강제로 열어주는 **브리지 페이지**를 거치게 한다.

- 브리지 페이지: `oauth-open.html` (이 저장소에 추가 완료, GitHub Pages로 서빙)
- 접속 주소: `https://<MOIDA 사이트 주소>/oauth-open.html`
- 사용법: `oauth-open.html?url=<URL인코딩된_구글OAuth주소>`
  - 카톡 → `kakaotalk://web/openExternal` 로 기본 브라우저 오픈
  - 안드로이드 기타 인앱 → `intent://` 로 크롬 강제 실행
  - 일반 브라우저 → 대상 주소로 즉시 통과
  - 자동 실행 실패 시 → "기본 브라우저로 열기" 버튼 + 링크 복사 + 안내 노출

## 스킬 서버 수정 (핵심 — 한 줄)
"연동이 만료됐거나 해제됐어요" 메시지의 **"내 캘린더 다시 연동하기" 버튼 링크**를 브리지로 감싼다.

```js
const BRIDGE = 'https://<MOIDA 사이트 주소>/oauth-open.html?url=';

// 기존 — 구글 OAuth 주소를 버튼 링크에 그대로 사용
const authUrl = oauth2Client.generateAuthUrl({
  access_type: 'offline',
  scope: ['https://www.googleapis.com/auth/calendar'],
  state: kakaoUserId,        // (사용자 식별용 — 그대로 유지)
  prompt: 'consent',
});
button.webLinkUrl = authUrl;                 // ← 이 줄을 아래로 교체

// 변경 — 브리지 페이지로 감싸서 사용
button.webLinkUrl = BRIDGE + encodeURIComponent(authUrl);
```

> `state`(사용자 식별값)는 authUrl 안에 그대로 실려 브리지를 통과하므로, 어느 카톡 사용자인지 구분은 그대로 유지된다.

## (권장) 콜백 완료 페이지에 "카톡으로 돌아가기"
외부 브라우저에서 로그인이 끝나면 사용자는 크롬/사파리에 남는다.
OAuth **redirect_uri 콜백 페이지**에 "연동 완료! 카톡으로 돌아가세요" 안내와 아래 버튼을 넣으면 UX가 매끄럽다.

```html
<a href="kakaotalk://">카카오톡으로 돌아가기</a>
```

## 확인 체크리스트
1. "내 캘린더 다시 연동하기" 클릭 → **크롬/사파리(외부 브라우저)** 로 열림
2. 구글 로그인 화면이 `disallowed_useragent` 없이 정상 표시
3. 로그인·권한 동의 완료
4. 카톡으로 돌아와 "내일 3시 안산모임 일정등록" → 일정 정상 등록

## 참고
- 구글 콘솔(OAuth 동의화면) 설정은 변경할 필요 없음. (본 오류는 브라우저 종류 문제)
- 만약 "이 앱은 Google에서 확인하지 않았습니다 / 테스트 사용자 아님" 같은 **다른** 오류가 뜬다면,
  그건 구글 콘솔의 동의화면(테스트 사용자 추가 / 앱 게시)에서 별도로 처리해야 한다.
