# 한주 · 주간행사 일정 등록 담당

전문 직원 `weekly_events`를 실제 에이전트 배정 목록에 추가한다. 기본 팀과 CRM 담당자는 유지한다. 현재 단계는 담당 조건 저장 및 요청형 첨부 분석이며, 네이버 메일 감시/자동 등록은 아직 구현·활성화되지 않았다.

## 설정

직원 상세의 ‘담당 메일·등록 조건’에서 메일함, 허용 발신자, 선택적 제목 조건, 플로우 프로젝트 이름을 저장한다. 개인 주소는 공개 소스에 넣지 않고 인증된 계정의 D1 `weekly_events_config`에 저장한다. 발신자는 정확한 주소 일치이며 제목 조건이 있으면 AND로 적용한다. 같은 발신자는 하나로 합친다. 담당 조건에는 비밀번호를 저장하지 않는다. 별도 네이버 연결 창에서 앱 비밀번호를 받아 TLS IMAP 로그인과 읽기 전용 EXAMINE INBOX 검사 후 계정별로 암호화 저장한다.

`GET/POST /weekly-events`는 현재 계정만 조회·저장한다. `enabled:true`는 거절한다. 에이전트의 `weekly_events_status`도 같은 실제 상태를 반환하므로 직원 추가를 자동화 시작으로 보고하지 않는다.

## 남은 연결

- 네이버 인증 검사·암호화 저장·재검사·해제는 GET/POST /naver-mail로 제공한다. 대상 호스트는 imap.naver.com:993으로 고정한다. 실제 인증은 사용자가 앱 비밀번호를 입력한 뒤 검증해야 한다.
- 연결 검사는 받은메일함 개수만 확인한다. 발신자별 원문/첨부파일 수신 어댑터와 전달 기능은 아직 구현되지 않았다.
- 실제 주간행사 첨부파일 형식 확인 및 원문 근거 기반 추출 검증.
- 플로우 프로젝트 ID 및 권한 검증. MCP 회사 사용량 한도에 도달하면 실행하지 않고 사용자에게 알린다. 한도 해제는 별도 계정 관리 작업이다.
- 지속 스케줄러, 메일 UID 처리 기록, 원문/일정 중복 지문, 등록 응답 유실 시 재전송 금지 및 수정·취소 검토 흐름.

이 단계에서는 자동화 스케줄을 생성하지 않는다. 운영 체크가 모두 준비된 후 사용자가 승인한 메일 범위에 한정해 활성화해야 한다.

검증: `node --test tests/weekly-events.test.mjs`에서 주소/제목 필터, 중복 주소 제거, 계정 격리, 연결 전 활성화 차단 및 실제 직원 배정을 확인한다.
