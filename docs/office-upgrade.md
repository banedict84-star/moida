# 의정비서실 개편

- 기존 MOIDA 계정과 작업 큐를 재사용한다. 조직 화면은 `platform.html#agents`.
- 일정·의전실, 정책·자료실, 홍보·콘텐츠실, 지역협력실, 비서실장 직속으로 기존 37개 역할을 묶는다.
- 사무실 화면에서 지시를 접수하고 팀장·담당자의 실제 작업 상태를 확인한다.
- 독립 팀은 최대 3팀 병렬 실행한다. 홍보팀은 사실을 제공하는 선행 팀, 기록팀은 실무 팀, 검증팀은 전체 실무 결과를 기다린다.
- 팀장 검토는 기존 최소 글자 수 검사에서 모델 기반 내용 대조·수정으로 변경했다. 확인 불가 사실을 외부 검증 완료로 취급하지 않는다.
- 새로 추가된 팀장 검토 호출은 품질 개선이며 단일 작업의 지연과 비용을 늘릴 수 있다. 병렬화는 독립 팀이 여러 개인 요청의 순차 대기를 줄인다. 실제 운영 지연 개선율은 아직 측정하지 않았다.
- 모델은 변경하지 않았다. 일반 대화는 프런트엔드의 GPT_MODEL(`gpt-4o`), 작업 큐는 서버의 AGENT_MODEL(`gpt-4o-mini`) 설정을 사용한다. 상태 API가 실제 작업 모델을 반환한다.
- 기존 역할 메모는 브라우저 표시용이며 실제 AI 실행 프롬프트를 바꾸지 않는다. 화면에서도 이 제한을 명시한다.

검증: 에이전트 분류, 실행 순서, 병렬 실행, 실패 정리, 모델 검토 응답, 상태 API 및 사용량 테스트 16개 통과. 플랫폼 내 인라인 스크립트 19개 구문 검사 통과.
전체 기존 테스트에서는 이번 변경 전 원본에서도 재현되는 실패 4개(1인 발의 분류 1개, 브랜드 마크 검사 2개, 웹자보 단계 문구 검사 1개)가 있다. 관련 없는 구현은 변경하지 않았으며 배포 검사는 변경된 에이전트 영역과 사용량 검사를 대상으로 한다.
