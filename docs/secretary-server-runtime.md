# 비서실장 서버 실행 1차 변경

## 범위

새 웹 클라이언트가 `server_runtime: true`로 접수한 비서실장 요청은 서버에서 도구 호출과 결과 전달을 진행한다. 기존 요청은 기존 방식으로 처리한다. 최신 운영 코드의 전문 직원 배정을 보존하며, 직원 실행·보고도 서버 실행 단계에서 이어간다. DOTS 전체 기능을 구현한 변경은 아니다.

실행 흐름: 요청 저장 → 서버 실행 등록 → 제공자 상태 확인 → 허용된 도구 선점 → 실제 결과 저장 → 제공자에게 전달 → 최종 답변 저장 → 대화 재접속 시 복구.

## 코드

- `secretary-runtime.js`: D1 실행 목록, 재시도 지연, 작업 선점, 실행 한도, 계정별 복구 조회.
- `secretary-agent.js`: 기존 도구 권한 및 호출 검증을 사용하는 서버 실행 단계.
- `gpt-worker.js`: 요청 이후의 실행과 매분 cron 연결. 기존 Queue 및 자동화는 유지.
- `secretary-client.js`: 서버 관리 요청에서는 브라우저 도구 실행을 하지 않고 상태만 조회. 재접속 복구.
- `platform.html`: 요청별 고정 결과 ID를 사용해 같은 최종 답변을 중복 추가하지 않음.

## 실행과 권한

- 상태와 결과는 기존 `secretary_turns` / `secretary_calls`에 저장한다. 새 `secretary_runtime` 테이블은 실행 예약과 선점을 담당한다. 기존 테이블 삭제나 변경은 없다.
- 실행 선점은 조건부 UPDATE로 처리한다. 서버 호출이 겹쳐도 같은 업무를 동시에 진행하지 않는다.
- 브라우저의 `/claim` 및 `/result` 요청으로 서버 관리 업무를 실행하거나 결과를 바꾸지 못한다.
- 도구 실행 직전에 AI 사용 허용 여부를 다시 확인한다. 메일·문자·MCP 등의 기존 준비/승인 절차는 유지한다.
- 응답 유실, 실행 중 프로세스 종료 등 실제 실행 여부가 불확실하면 자동 재실행하지 않고 `needs_attention`으로 보관한다.
- 일시 오류는 지연 재시도하며 연속 5회 실패, 권한·상태 오류, 240단계 한도에 도달하면 확인 필요 상태로 전환한다.
- 요청 후 `waitUntil`은 빠른 실행을 위한 보조 경로다. 브라우저가 닫혀도 매분 cron이 다음 단계를 처리한다. 회당 최대 10개 업무, 업무당 도구 호출 1개를 처리하므로 즉시 실행을 보장하지 않는다.

## 복구와 남은 범위

- 완료 답변은 서버에 남고, 대화를 다시 열면 최근 서버 업무 최대 50건과 결과물 참조를 복구한다. 이 한도는 조회 한도이며 DB 기록을 삭제하지 않는다.
- 현재 채팅 목록에 있는 대화를 열 때 복구한다. 접수 직후 사용자 메시지 자체의 클라우드 저장 전에 앱이 종료되는 경우의 다른 기기 대화 발견은 별도 보완이 필요하다.
- 결과 파일은 기존 저장·다운로드 기능을 사용한다. 새 파일 저장소를 추가하지 않았다.
- 목표 기반 후속 판단, 푸시 알림, 대시보드 통합, 확인 필요 작업의 취소·복구 관리 화면은 이번 변경에 포함하지 않았다. 브라우저에 의존하는 기존 CRM 조회는 화면이 열려 있어야 이어진다.
- API 공급자 요청과 도구는 모의 응답으로 검증했다. 운영 서버 및 실제 계정에서의 앱 종료 테스트는 배포 후 별도로 필요하다.

`node --test tests/secretary-agent.test.mjs tests/parallel-chats.test.mjs tests/secretary-toolkit.test.mjs tests/secretary-builtin-tools.test.mjs tests/secretary-feature-tools.test.mjs tests/chat-archive.test.mjs`

브라우저 없이 서버만으로 완료, 동시 실행 중복 방지, 응답 유실 시 재실행 방지, 권한 해제, 계정 간 격리, 로컬 저장소 없는 복구, 브라우저가 서버 도구를 대신 실행하지 않는 경우를 포함한다.

## 배포

Worker와 웹 화면을 함께 배포해야 한다. Worker를 먼저 배포하면 이전 클라이언트는 기존 실행 방식을 유지한다. 새 클라이언트는 `server_runtime` 플래그와 `/secretary/background`를 사용한다. 배포된 서버는 `/health`의 `secretaryRuntime: server-runtime2`로 확인한다.
